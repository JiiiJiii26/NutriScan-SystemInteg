1. Project Overview

NutriScan is a web-based dietary management application tailored for Filipino college students to monitor their daily caloric and nutritional intake from packaged grocery foods (e.g., instant noodles, canned goods, and student snacks). The system integrates barcode identification, nutritional diary logging, and user accounts to assist students in tracking their diet on a student budget.

Core feature for this increment: User Profile Management & Account Security Lifecycle (Profile Editing, Authenticated Password Change, and Token-Based Password Reset).

Justification: Self-service profile and credential lifecycle management is critical for student data integrity and application security. It ensures students can manage their personal profiles, maintain account security through password rotations, and recover account access independently without requiring manual database administrative intervention.

2.2 Core Feature: User Profile and Security Lifecycle

Description: Provides students with full self-service control over their identity and credentials. Local account students can modify their full name, update their registered email, and change their active password by verifying their existing credentials. Students who forget their password can initiate an unauthenticated recovery request, which generates a cryptographically secure, time-limited (15-minute) reset token to safely set a new password.

User Roles and Access

RoleWhat this role can do in the feature

Unauthenticated Guest Cannot view or modify profile endpoints (enforced 401 Unauthorized); can request password reset token via /api/auth/forgot-password and complete reset via /api/auth/reset-password.

User Flow

  1. Profile Editing: Student logs in and navigates to /profile. Student edits Full Name or Email and clicks "Save Profile Changes". Input is validated, updated in PostgreSQL, and the top-right Navbar updates in real-time.
  2. Password Change (Authenticated): Under "Security & Password", student inputs Current Password, New Password (min. 8 chars), and Confirm New Password. Backend validates against stored BCrypt hash, encodes new password, and saves. Old password immediately fails on next login.
  3. Forgot & Reset Password (Unauthenticated): On login screen, student clicks "Forgot Password?". Entering email generates a 15-minute secure token logged in the backend console (simulating mail delivery). Student accesses /reset-password?token=..., sets new password, token is marked as consumed, and student logs in with new credentials.
